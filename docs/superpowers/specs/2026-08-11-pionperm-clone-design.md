# Клон сайта pionperm.ru на Next.js — дизайн

Дата: 2026-08-11

## Контекст

Владелец салона цветов и подарков «Пион» (Пермь) хочет получить копию своего действующего сайта pionperm.ru (сейчас на конструкторе Tilda) в виде обычного кода, чтобы иметь возможность разместить его на любом хостинге и дальше развивать самостоятельно. Клон должен визуально совпадать с оригиналом один в один: те же страницы, тексты, фотографии, каталог товаров, слайдеры и формы.

## Цели

- Полное покрытие сайта: все 27 страниц из sitemap.xml (главная, каталог и его категории, статичные и промо-страницы).
- Визуальное соответствие 1:1: вёрстка, шрифты, цвета, отступы, анимации (карусели/слайдеры).
- Реальные фотографии и тексты с оригинального сайта (сайт принадлежит заказчику).
- Рабочая корзина и формы на фронтенде (валидация, состояние), но без реальной интеграции оплаты/CRM — это отдельная задача на будущее.

## Технологический стек

- **Next.js 14 (App Router) + TypeScript** — по выбору заказчика.
- Обычный CSS (CSS Modules) для стилей, без UI-фреймворков — воспроизводим фирменный стиль напрямую из CSS оригинала.
- Данные каталога и статичных страниц — локальные JSON-файлы (не CMS, не БД).
- Изображения — локальные файлы в `public/images/...`, скачанные с оригинального сайта.

## Сбор данных (скрейпинг)

Сайт на Tilda рендерит контент на сервере (HTML отдаётся сразу, без клиентской подгрузки через API), поэтому весь контент можно вытащить обычным HTTP-запросом + парсингом HTML.

Скрипт `scripts/scrape.mjs` (Node, `cheerio` + `undici`/`fetch`):

1. Читает список URL из `https://pionperm.ru/sitemap.xml`.
2. Для каждой страницы:
   - Категории каталога (`/bukety`, `/korziny`, `/korobki`, `/flowers`, `/wedding`, `/balloons`, `/chocolate`, `/flame`, `/indoorflowers`, `/pions`, `/roses`, `/mixflower`, `/luchshee`) — парсит карточки товаров: название, состав (описание), цена, URL фото. Пишет в `data/catalog/<slug>.json`.
   - Статичные и промо-страницы (`/about`, `/delivery-and-payment`, `/flower-delivery`, `/contacts`, `/uds`, `/stock`, `/policy`, `/valentinesday`, `/new-year-2025`, `/doza_endorfina`, и т.д.) — вытаскивает текстовые блоки (заголовки, параграфы) и изображения в порядке следования, пишет в `data/pages/<slug>.json`.
   - Главную (`/`) — отдельно: слайды hero-карусели (11 шт.), блок «Новинки», блок преимуществ, футер.
3. Скачивает все найденные изображения в `public/images/<категория>/<файл>` (по оригинальному имени файла), заменяет URL в JSON на локальный путь.
4. Скрипт идемпотентен: повторный запуск не перекачивает уже скачанные файлы.

Скрипт запускается один раз вручную (`node scripts/scrape.mjs`) в рамках разработки; сам сайт на рантайме данные не тянет — использует то, что лежит в `data/` и `public/images/`.

## Структура страниц

- `app/page.tsx` — главная (hero-слайдер, новинки, преимущества, промо-баннер, UDS-блок).
- `app/catalog/page.tsx` — обзорная страница каталога со ссылками на категории.
- `app/[category]/page.tsx` (или отдельные папки на каждую категорию) — сетка товаров, использует общий компонент `CategoryGrid`, наполняется данными из `data/catalog/<slug>.json`.
- `app/about`, `/delivery-and-payment`, `/flower-delivery`, `/contacts`, `/uds`, `/stock`, `/policy` — статичные страницы, рендерят блоки контента из `data/pages/<slug>.json` через общий компонент `ContentBlocks`.
- Промо-лендинги (`/valentinesday`, `/new-year-2025`, `/doza_endorfina` и т.п.) — тот же `ContentBlocks`, т.к. это, по сути, наборы текст+картинка+кнопка.

## Компоненты

- `Header` — лого, меню, телефон, адрес, соцсети (VK/Telegram/WhatsApp), кнопка «Сделать заказ», иконка корзины со счётчиком.
- `HeroSlider` — карусель баннеров на главной (автопрокрутка, точки, стрелки).
- `ProductCard` / `CategoryGrid` — карточка товара (фото, название, состав, цена, кнопки «Описание» / «Купить похожий») и сетка с сортировкой (цена/название/новизна — та же логика, что на оригинале).
- `Footer` — блок VK, ссылки «Букеты»/«Декор»/«Информация», реквизиты ИП, соцсети.
- `CartDrawer` — выезжающая панель корзины, состояние в React Context + `localStorage`, подсчёт суммы.
- `CheckoutForm` — форма оформления заказа (имя, email, телефон, способ доставки/оплаты) с валидацией на фронте.
- `BouquetBuilderPopup` — многошаговый попап «Собери свой букет» (тип, гамма, размер, бюджет, дата, контакты).
- `ContentBlocks` — универсальный рендерер текстовых/фото-блоков для статичных и промо-страниц.

## Корзина и формы (важное ограничение)

Реальной интеграции нет:
- Корзина хранится в `localStorage`, полностью работает на фронте.
- `CheckoutForm` и `BouquetBuilderPopup` проходят валидацию и на сабмите показывают экран-заглушку «Спасибо, мы с вами свяжемся» — без реальной отправки на сервер, в CRM или интеграции с T-Bank.
- Позже это можно donастроить отдельно (email/Telegram-уведomления, приём платежей), когда заказчик определится с провайдером/бэкендом.

## Не входит в объём

- Backend/API, реальная отправка заказов, платежи, админка/CMS для редактирования каталога.
- Полная пиксель-перфект-копия анимаций Tilda (используем аналогичные CSS-анимации/переходы, не JS-библиотеку Tilda).
- SEO-метатеги/аналитика оригинала (можно добавить по запросу).

## Тестирование

- Ручная проверка каждой страницы в браузере на соответствие оригиналу (вёрстка, фото, тексты).
- Проверка адаптива (мобильная/десктопная раскладка), т.к. оригинал адаптивный.
- Проверка работы корзины (добавление/удаление, подсчёт суммы, persist после reload) и валидации форм.
